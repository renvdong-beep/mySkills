# 项目目录迁移/重构

当需要将项目中的目录或文件移动到新位置时，确保所有引用路径不断裂。

## 触发条件
- 用户要求移动/重命名目录或文件
- 目录结构调整导致路径变化

## 执行步骤

1. **全局搜索引用点**
   - 用 Grep 搜索目标目录名在所有代码中的引用
   - 同时搜索子目录/文件名（如 `目标目录/sub/path`）
   - 不要遗漏 Python、Shell、JSON、spec 等各类文件

2. **分析路径构建方式**
   - 区分每种引用的路径基础变量（如 `PROJECT_ROOT`、`GUI_DIR`、`__file__`、`sys._MEIPASS`、`SCRIPT_DIR` 等）
   - 记录每个引用的行号和具体拼接方式
   - 注意：不同项目的变量命名可能不同，需根据实际代码分析

3. **区分三种运行模式的路径**
   - **开发模式**：通常基于 `os.path.dirname(os.path.abspath(__file__))` 向上推导
   - **打包模式**：PyInstaller 打包后 `sys._MEIPASS` 指向 `_internal/`（或其他打包工具的等效路径）
   - **安装后模式**：安装目录下的资源路径，由打包配置（spec/datas 等）决定

4. **移动目录 + 修改引用**
   - 执行 `mv` 移动目录
   - 修改所有引用点的路径基础变量
   - 修改拷贝/构建脚本的源路径
   - 打包配置中的目标名通常不变（保证安装后路径一致）

5. **验证**
   - 确认旧目录已移除
   - 确认新目录存在且内容完整
   - 确认所有引用已更新（再次 Grep 检查）
   - 确认各运行模式下路径都能正确解析

## 注意事项
- 移动前先完整读取所有引用文件，不要遗漏
- 打包配置中 `(源, 目标)` 的目标名决定了安装后路径，不要随意改
- 构建脚本中的 cp 源路径要跟随目录位置变化
- 如果新增参数，要同步修改所有调用处
- 非打包项目可忽略打包模式相关步骤
