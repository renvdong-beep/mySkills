# 配置文件差异管理

管理不同环境（内网/外网/开发/生产）的配置文件差异。

## 触发条件
- 配置文件在不同环境有不同值（IP、路径、端口等）
- 需要同步代码但保留环境配置差异
- 用户提到"配置"、"环境差异"、"repo文件"

## 执行步骤

1. **识别配置差异文件**
   - 常见类型：.repo、.conf、.cfg、.json、.yaml、.env、.ini
   - 用 diff 对比两个环境的配置文件
   - 标记哪些是环境差异、哪些是功能差异

2. **环境差异处理策略**

   **策略A：模板 + 替换（推荐）**
   - 配置文件中用占位符：`baseurl=ftp://{{FTP_HOST}}/path/`
   - 构建时用 sed/envsubst 替换占位符
   - 好处：一份模板适配所有环境

   **策略B：多份配置**
   - 每个环境一份配置：`config.internal`、`config.external`
   - 构建时选择对应配置
   - 好处：简单直接

   **策略C：运行时替换**
   - 脚本中动态检测环境并替换配置
   - 如 build.sh 中的 `setup_build_repo()` 函数
   - 好处：一份代码自动适配

3. **同步时的处理**
   - 合并代码时：不覆盖目标环境的配置文件
   - 只合并功能改动，环境值保留各自版本
   - 如果配置结构有变化（新增字段），需要同步

4. **验证**
   - 确认各环境配置值正确
   - 确认构建时能正确读取配置
   - 确认合并后配置文件格式无误

## 注意事项
- IP 地址是最常见的环境差异，不要在合并时覆盖
- 路径差异（如 `/opt/` vs `/usr/local/`）也是环境差异
- 新增配置项时，所有环境都需要添加（值可以不同）
- 敏感配置（密码、密钥）不要明文写在配置文件中
